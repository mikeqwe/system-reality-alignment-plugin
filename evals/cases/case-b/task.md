Implement the projection contract in projection.py and add focused tests. Keep the public apply(state, event) API; no new dependencies or infrastructure. Each event is a dictionary with exactly subject (a nonempty string), revision (a positive integer, not bool), and status. Allowed status values are pending, active, failed. The authenticated source is authoritative per subject; higher revision supersedes lower revision even when status goes from active back to pending. Delivery can be duplicated or reordered. Exact repeated revisions are no-ops; a different status at the same revision is a conflict and raises ValueError without changing state. Invalid events raise ValueError without changing state (including unknown fields and bool revisions). Missing subjects remain absent/unknown. State values are dictionaries containing revision and status. Implement only these requirements; do not infer time order, add an event store, or claim production behavior was tested. Do not mutate the input event or retain mutable aliases to it.
